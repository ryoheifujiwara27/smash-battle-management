# SMASH RECORD — スマブラSP 戦績トラッカー

大乱闘スマッシュブラザーズ SPECIAL の勝敗を記録・分析できる、ビルド不要の Web アプリです。
データはブラウザの **localStorage** に保存されるため、サーバーもアカウントも必要ありません。
必要に応じて **Supabase によるクラウド同期**（別端末での共有・サイトデータ削除からの復元）を
後から有効にできます。設定しなければ従来どおり完全にローカルで動作します。

## 使い方

`index.html` をブラウザで開くだけで動作します。

- ローカル: ファイルをダウンロードして `index.html` をダブルクリック
- GitHub Pages: リポジトリの Settings → Pages で `main` ブランチのルートを公開すると、そのまま Web アプリとして使えます

## 機能

| タブ | 内容 |
| --- | --- |
| 記録 | 自分のキャラ / 相手のキャラ / 勝敗 / メモ（任意）を入力して保存。累計の対戦数・勝敗・勝率を常時表示 |
| 履歴 | 過去の対戦を新しい順に一覧表示。相手キャラでの絞り込み、1件ずつの削除、JSON の書き出し / 読み込み、全削除 |
| 分析 | 相手キャラ別の対戦数・勝利数・勝率(%) をランキング表示（勝率順 / 対戦数順 / 勝利数順 / 苦手順）。自分のキャラでの絞り込みと、自キャラ別の戦績も表示 |

- 参戦ファイターは全 86 種（ダッシュファイター・Mii ファイター 3 種を含む）を収録しています。
- キャラクター選択はアイコン付きのグリッドから行えます（キャラ名・シリーズ名・slug で検索可能）。
  履歴や分析画面でもキャラ名の横にアイコンを表示します。
- ダーク基調のデザインで、スマートフォン画面に最適化したレスポンシブレイアウトです。

## ファイル構成

```
index.html          画面のマークアップ
styles.css          スタイル（ダークテーマ / レスポンシブ）
characters.js       ファイター一覧・シリーズ定義・アイコン設定
app.js              記録・保存・集計・キャラ選択ロジック
sync.js             クラウド同期（認証・マージ）※任意
supabase-config.js  Supabase の接続設定 ※任意
supabase/schema.sql Supabase に流すテーブル定義と RLS ※任意
assets/icons/       キャラアイコン画像の配置先（既定では空）
```

ビルド手順は不要です。クラウド同期を有効にした場合のみ、CDN から
Supabase クライアントを読み込みます（未設定時は読み込みに失敗しても動作に影響しません）。

## キャラアイコンについて

既定では画像を同梱せず、**シリーズカラー＋頭文字のアバター**を表示します。
オフラインでも必ず表示され、外部サービスへの依存もありません。

実際のキャラ画像を使う場合は、次のどちらかを設定してください。

1. `assets/icons/` に `<slug>.png`（例: `mario.png`, `cloud.png`）を置く
2. `characters.js` 冒頭の `ICON_BASE` を任意の URL テンプレートに変更する
   ```js
   var ICON_BASE = 'https://example.com/ssbu-icons/{slug}.png';
   ```

slug は `characters.js` の各ファイターに定義されています。詳細は
[`assets/icons/README.md`](assets/icons/README.md) を参照してください。

フォールバックは二段構えです。

- 起動時に 1 枚だけ試験読み込みし、取得できない環境ではそれ以上リクエストを出さず
  アバター表示に切り替えます（画像未配置時、コンソールに 404 が 1 件だけ出ます）。
- 個別の画像が欠けている場合も、そのキャラだけアバター表示に切り替わります。

なお、ゲーム内のファイターアートワークは任天堂および各権利者の著作物のため、
このリポジトリには画像を同梱していません。

## データについて

既定（クラウド同期を設定していない状態）では、次のようになります。

- 保存先はブラウザごとの localStorage（キー: `smash-record/battles/v1`）です。
- ブラウザを閉じたり端末を再起動しても記録は残ります。
- ただし次の場合は失われます。
  - ブラウザの**サイトデータ / 閲覧履歴を削除**したとき
  - **シークレットウィンドウ**を閉じたとき
  - iOS / macOS の Safari で**7 日間アクセスしなかった**とき（ITP による自動削除。
    ホーム画面に追加して起動すると対象外になります）
- **別の端末やブラウザとは共有されません。**

これらを解消するのが次のクラウド同期です。設定しない場合は、「履歴」タブの
JSON 書き出し / 読み込みが移行・バックアップ手段になります。

## クラウド同期のセットアップ

[Supabase](https://supabase.com) の無料プロジェクトを使って、記録をクラウドに保存します。
有効にすると、**別の端末から同じデータを見られ**、サイトデータを削除しても
**再ログインで完全に復元**できます。所要 5 分程度です。

### 1. Supabase プロジェクトを作る

[supabase.com](https://supabase.com) でプロジェクトを作成します（無料枠で十分です）。

### 2. テーブルを作る

ダッシュボードの **SQL Editor** を開き、[`supabase/schema.sql`](supabase/schema.sql)
の内容をそのまま貼り付けて実行します。対戦記録用のテーブルと、
**他人にデータを読まれないための Row Level Security** が設定されます。

### 3. 接続設定を書く

**Project Settings → API** にある `Project URL` と `anon public` キーを、
[`supabase-config.js`](supabase-config.js) に記入します。

```js
var SUPABASE_CONFIG = {
  url: 'https://xxxxxxxxxxxx.supabase.co',
  anonKey: 'eyJhbGciOi...'
};
```

> `anon` キーはブラウザに配布される前提の公開鍵なので、コミットして問題ありません。
> 実際のデータ保護は手順 2 の Row Level Security が担います。
> **`service_role` キーは絶対に書かないでください**（RLS を無視できる管理者キーです）。

### 4. ログイン用のメール設定

**Authentication → URL Configuration** の `Redirect URLs` に、アプリを公開している
URL（例: `https://<ユーザー名>.github.io/smash-battle-management/`）を追加します。

これでアプリの「履歴」タブに表示される**クラウド同期**カードから、
メールアドレスでログインできるようになります。届いたメールのリンクを開けばログイン完了です。

> **補足:** メール内のリンクではなく 6 桁コードで入力したい場合は、
> **Authentication → Email Templates → Magic Link** のテンプレートに `{{ .Token }}` を
> 追加してください。アプリ側はどちらの方法にも対応しています。
> なお `file://` で直接開いた場合はリダイレクトが働かないため、コード入力をご利用ください。

### 同期の仕組み

- **ローカルファースト**: 保存は常にまず localStorage に書かれ、画面は即座に更新されます。
  通信は裏で行われるため、オフラインでも通常どおり記録できます。
- **自動同期**: 記録の追加・削除時、アプリを開いたとき、オンラインに復帰したとき、
  タブを再表示したときに同期されます。「今すぐ同期」で手動実行もできます。
- **競合の解決**: レコード単位で `updatedAt` が新しい方を採用します（last-write-wins）。
- **削除の伝播**: 削除は論理削除として記録されるため、別の端末で消した記録が
  同期によって復活することはありません。
- **ログアウトしても**この端末のデータは残ります。同期が止まるだけです。
